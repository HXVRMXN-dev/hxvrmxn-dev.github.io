Cordwire

A modernized DiscordAcePerms. Cordwire keeps your server's ACE permission groups in sync with your Discord roles automatically — no manual re-adding principals every time staff changes.

Standalone, framework-agnostic

Cordwire only talks to Discord and your server's ACE system — it doesn't depend on ESX, QBCore, or any specific framework.

Overview

On start, Cordwire pulls each linked player's Discord roles and maps them to ACE groups defined in your config. It re-checks on a timer and on Discord role-update events (via bot mode), so promotions and demotions in Discord apply in-game without a restart.

  • Two sync modes: lightweight webhook polling or a full bot connection for near-instant updates.
  • Role → ACE group mapping defined entirely in config.lua, no database required.
  • Exports to read a player's current synced group from other resources.
  • Console logging with a dry-run mode so you can verify mappings before going live.

Installation

  1. Download the latest release from the GitHub repo and drop the cordwire folder into your server's resources directory.
  2. Create a Discord application at the Discord Developer Portal and invite the bot to your server (or generate a webhook, depending on the mode you choose).
  3. Copy config.example.lua to config.lua and fill in your guildId, bot token or webhook URL, and role mappings.
  4. Add the following to your server.cfg, above any resources that depend on ACE permissions:
server.cfg
ensure cordwire
Load order matters

Cordwire needs to start before any resource that checks ACE permissions on player join, or those checks may run before groups are assigned.

Configuration

All settings live in config.lua. The core of it is the role map, which pairs a Discord role ID with an ACE group name:

config.lua
Config.Discord = {
  guildId       = "123456789012345678",
  mode          = "bot",        -- "bot" or "webhook"
  botToken      = "YOUR_BOT_TOKEN",
  refreshSeconds = 120,
}

Config.RoleMap = {
  ["998877665544332211"] = "admin",
  ["887766554433221100"] = "moderator",
  ["776655443322110099"] = "support",
}

Config.DryRun = false -- log intended changes without applying them
KeyTypeDescription
Discord.modestring"bot" for live role-update events, "webhook" for lightweight polling only.
Discord.refreshSecondsnumberHow often Cordwire re-checks roles in webhook mode.
RoleMaptableDiscord role ID → ACE group name. A player can hold multiple mapped roles.
DryRunbooleanWhen true, Cordwire logs what it would change without touching ACE.

Exports & Events

Other resources can read a player's synced state or react to sync changes:

server-side export
local group = exports.cordwire:GetSyncedGroup(source)
-- returns the ACE group string, or nil if unsynced
Export / EventSideDescription
GetSyncedGroup(source)Server exportReturns the player's currently synced ACE group.
ForceRefresh(source)Server exportImmediately re-checks a single player's Discord roles.
cordwire:playerSyncedServer eventFires after a player's ACE group is assigned or changed.
cordwire:playerUnlinkedServer eventFires when a player has no Discord account linked.

FAQ

The bot connects but roles never sync

Double-check the bot has the Server Members Intent enabled in the Developer Portal — without it, Cordwire can't read member roles even with a valid token.

Can I map one Discord role to multiple ACE groups?

Not directly in RoleMap, but you can listen for cordwire:playerSynced in your own resource and grant additional principals from there.

Webhook mode isn't picking up changes fast enough

Webhook mode only polls on the interval set by refreshSeconds. Switch to mode = "bot" for near-instant updates driven by Discord's gateway events instead.

Players aren't linked to Discord at all

Cordwire relies on your server already having Discord identifiers attached to players (standard with FiveM's Discord identifier). If a player joined without Discord linked, Cordwire fires cordwire:playerUnlinked and leaves their ACE group untouched.
